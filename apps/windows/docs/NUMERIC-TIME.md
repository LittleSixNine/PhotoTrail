## IPTC部分日期

两个目标独立设置／删除，不填另一部分，不改变EXIF／XMP主时间或列表、地图、GPX拍摄时间。严格公历1500-02-29拒绝，1600-02-29允许。接受完整合法时间时只提取指定部分并去亚秒；时间部分仍须原文明确偏移，Z规范为+00:00。部分日期不进入完整日期页五模式。

沿R04b原始IIM与编码保护：首次设置声明标准UTF8；已有未声明ASCII、旧／未知／冲突编码设置仍拒绝。纯删除不指定解码，剩余原始数据集、版本、声明与非目标Photoshop资源逐字节保持。无 ApplicationRecordVersion 的遗留块纯删除时，工具若自动补版本，回读拒绝交付；不宣称所有遗留块都可安全删除。日期/时间ASCII也不能绕过设置资格。此前12目标的UTF8字节、列表及国家代码规则保持。

## Windows文件时间契约

Windows API直接读取实际目标FILETIME，独立回读，避免 .NET UTC读取经本机偏移转换时在9999年溢出。接受`yyyy:MM:dd HH:mm:ss`、可选1—9位亚秒及Z／±hh:mm。显式偏移优先，无偏移按本机时区；DST无效／歧义拒绝，不猜UTC或静默归一。冻结本机时区、实际UTC时刻、创建／修改属性及revision；时区或外部仅改属性而SHA相同仍使计划失效。文件时间不作为ExifTool标签写入。

本批无损100ns：第8／9位仅允许零，不舍入；规范输出7位小数与+00:00。实际可设置下界1601-01-01 UTC加100ns，上界9999-12-31 23:59:59.9999999 UTC；超出UTC范围拒绝。FILETIME零值在设置API中表示保持原属性，1601-01-01 00:00:00整秒明确拒绝。原属性不可无损重现时暂存／备份核对失败，真实目标不改写。实际回读要求tick完全相同，严于Mac严格小于10微秒的匹配容差；不把两平台表示精度写成一样。

纯文件时间副本不运行ExifTool改写、不增元数据，图片字节保持；只改输出JPEG的请求属性，原图字节／创建修改时间与会话草稿保持。混合修改先在同一暂存完成元数据与请求属性，再提交并实际回读；没有“元数据成功、时间失败仍整件成功”。交付后未确认的副本保留，按unknown处理；原位提交后取消／属性回读／UI接纳失败保持unknown、原草稿和事务材料，禁止同目标盲重试。

## 新旧恢复记录

含System目标的新原位记录为v2，记录原属性、已核验保存后属性与文件身份；恢复另存当前字节和属性，然后恢复原完整SHA与原创建／修改时间。相同SHA不等于没写入，结果分类还核对文件身份和属性。重复恢复及外部仅改时间拒绝。

普通元数据记录仍v1；既有v1无新增保存后属性时沿原属性保护读取／恢复，不改写历史记录。未知版本或新v2属性缺失／不匹配拒绝。原位仍限已验固定NTFS普通权限目标，TxF不可用安全拒绝，不改为无保护就地写。历史损坏／unknown／未完成记录及不一致／缺失备份保留，不自动修复。
