# PhotoTrail 功能与数据约定

## 设置

设置的“通用”页提供“反馈意见”按钮，打开默认邮件应用，收件人为 liujiudexiaohao@gmail.com，预填主题 PhotoTrail Feedback。正文预填运行中应用的版本号和构建号，并留出问题描述区域；用户可以编辑后自行发送。不自动附加照片、轨迹、日志或设备信息；页面也显示可复制的邮箱地址。

设置窗口按通用、地图、元数据、照片与保存、轨迹、存储分组。通用可选择下次启动打开元数据编辑、地图定位、重命名或上次工作区；默认恢复上次工作区，首次使用打开元数据编辑，旧地图页面偏好继续兼容。元数据设置可勾选常用字段（含只读字段）、搜索名称或标签并恢复默认；默认 25 项包括文件名／路径、EXIF／IPTC／XMP 日期时间、EXIF 相机与曝光、GPS 经纬度／方向／日期时间。只改变常用视图，完整视图、全字段搜索与写入权限保持原有行为。存储显示历史轨迹数量、轨迹缓存占用及已转换数量，清除高德转换缓存前须确认，保留原轨迹文件、历史几何与权限书签，迟到的转换结果不重新填回已清除缓存；清除失败保留当前内存数据。默认显示全部照片标记；关闭“在地图上显示所有照片的位置”后，仅显示选中照片的位置。默认允许双击地图和拖动照片标记定位，地区名称自动查询。地图启动视野默认尝试设备位置，定位不可用时回退该地图来源的上次视野，没有记录时使用原预设位置；也可选择直接恢复上次视野。主界面的地图来源、标准／卫星和高德凭据入口与设置共用偏好及钥匙串记录。关闭地区名称自动查询不会关闭地图搜索、图块或高德选点校验。

“保存前显示修改摘要”默认关闭。开启后，工具栏保存和 ⌘S 均在写入前列出本地照片、XMP、照片图库的实际待保存件数及备份状态；取消不会开始保存或清除撤销记录。

元数据编辑与地图定位共用全局待保存集合，并在窗口右上角共用同一个“写入所有元数据”工具栏按钮，沿用地图页的样式、位置及状态逻辑；切换页面不改变其位置。元数据面板和批量操作侧栏不再重复放置写入按钮。“写入所有元数据”和 ⌘S 保存当前窗口内两个页面产生的全部待保存修改，不受当前页、选中照片或筛选范围限制；重命名不属于此保存集合。鼠标连续悬停按钮 2 秒后显示浮窗：“新的信息将写入文件，包括照片信息与定位修改，不限当前选中的照片。”离开按钮取消等待并关闭提示，点击按钮也关闭提示；辅助功能直接提供相同说明。保存摘要明确说明范围，元数据页显示全局待保存数量，即使当前未选照片也可保存。左栏的布局调整不改变定位和轨迹匹配的数据处理。

对原有日期／定位保存路径，启用“创建 XMP 附属文件”后，没有同名 XMP 的本地照片会先创建附属文件，本次修改写入新 XMP，原图元数据不改。若保存期间已经创建 XMP 但后续步骤失败，界面仍按实际文件来源切换到 XMP，并保留未保存状态供重试；创建流程不会覆盖保存期间新出现的同名 XMP。

对原有日期／定位保存路径，启用“给更新的文件添加 Finder 标签”后，标签写入作为元数据保存后的独立步骤。若元数据已成功写入而仅 Finder 标签失败，照片仍标记为已保存，并提示标签未添加；其他文件的元数据写入失败仍保留待保存状态。

新会话默认使用系统相机时区；指定时区只影响随后新建的会话，当前批次仍可单独调整。从照片创建 GPX 的断段默认间隔为 5 分钟，两个创建入口都允许本次临时调整。JPG／RAW 同名配对及递归导入默认开启；配对开关仅作用于后续导入，已导入照片的分组保持不变。备份清理默认仅提醒超过 7 天的旧备份，可改为 30、90 天或不提醒，删除仍须确认。

文件选择、拖入和文件夹导入共用同一导入筛选：照片列表只接收系统识别为图片的文件；混合导入会跳过其他文件并提示数量，GPX、KML、KMZ 仍按轨迹导入。旧版本已进入列表的不可编辑条目可在文件名上打开菜单，直接从列表移除；移除不删除原文件。

## 高德点选

1. 首次启动依次完成语言、备份、地图、确认四步引导；简体中文默认高德，其余六种语言默认 Apple 地图，仍可手动选择。打开测试照片副本。
2. 在地图设置菜单的“高德 API 设置”中填写自己的 Web 端 JS API Key 和 securityJsCode，保存到本机专用钥匙串记录。
3. 选中可编辑照片，在地图点选位置。程序先查询行政区，再将 GCJ-02 本地转换为 WGS84；调用一次高德官方正向转换检查，回到点击点的误差须不大于 5 米。
4. 检查提示后保存，关闭并重新打开副本验证。新位置标记 GPSMapDatum=WGS-84、GPSProcessingMethod=MANUAL。

高德凭据只保存在钥匙串；应用使用内存中的凭据填充设置界面，避免重复读取。若启动时拒绝钥匙串访问，可在高德设置中点“从钥匙串读取”再次请求并填充凭据。临时签名版本重新构建后仍可能触发系统授权。未配置密钥时不创建高德网页，地图区域显示完整的设置说明。

启用高德后，显示照片和校验选点会发送经纬度到高德；照片文件不会上传。
安全密钥会进入地图 JavaScript 运行环境；钥匙串仅保护本机存储。本原型采用官方文档中的开发方式，公开服务需要另行配置安全代理。

关闭主窗口或退出应用时，如有未保存修改，应弹出“有未保存的修改”，提供“继续编辑”和“放弃修改并退出”；默认继续编辑，不丢弃修改。保存正在进行时继续拦截退出。

## 数据约定与范围

- 高德经纬度仅用于地图交互；高德确认的新位置写入照片前转换为 WGS84。
- 原照片未声明 GPSMapDatum 时，只暂按 WGS84 显示，不据此修改或补标原始坐标系。明确声明其他基准的照片不显示原标记。
- 仅修改日期或地址时，保留 GPS；用户显式开启原版“更新 GPS 时间戳”选项时仍按该设置更新 GPS 时间。
- 本原型仅允许高德行政区代码确认为中国大陆的选点，未知、境外及港澳台点暂不写入。公式的数值边界不是国界判断。
- 苹果与高德默认显示全部有有效定位的导入照片，也可只显示选中照片；缩略图由原生层显示，不进入高德 JavaScript。拖动只更新稳定 ID 对应的单张照片，仍需手动保存。
- 本地逆转换是近似算法。往返误差测试验证计算一致性，不能证明实际拍摄位置精度。每次官方正向复核也不替代真实地点验收。
- Photos 图库通过苹果接口更新位置，不能自行设置图库导出照片的 EXIF 基准标签；需另行验证导出行为。

## 验收要求

先用公开地点和生成图片完成点选→保存→重开，再用私人目录的照片副本验收。
至少验证 JPEG、HEIC、RAW+XMP，以及取消保存、断网、快速切换照片、连续点选。
真实服务测试需要有效凭据；未提供凭据时，仅运行公式、元数据和地图交互的离线测试，不把模拟测试写成实测通过。
私人照片、真实拍摄位置、凭据和构建日志不提交到代码仓库。

## 搜索与收藏

详情页左侧显示经纬度、收藏地点和轨迹工具；地图来源和高德 API 凭据入口位于地图设置菜单。
苹果与高德共用地图左下角搜索浮层，结果分为地点名和地区两行；选择结果仅预览，点击“应用到照片”才修改位置。
地图设置菜单及设置窗口的“高德地图配色”提供全部 11 种官方配色，界面外观提供亮色、暗色和跟随系统（默认），设置窗口与地图设置菜单共用选择。亮色地图默认月光银，暗色默认幻影黑，两套搭配独立保存；跟随系统时按实际外观读取，重载及重启后恢复。旧版手动选择的配色保留为亮色搭配，卫星视图返回标准视图后继续使用所选配色。地图左上角可切换标准/卫星视图。地图启动默认请求一次系统定位以确定初始视野；右下角定位按钮可再次请求定位并移动地图。两者均不修改照片。
左栏默认宽度为窗口的 26%，照片条默认高度为 13%；拖动尺寸会保存在本机。地图左栏固定保留垂直滚动条槽位，滚动条仍沿用闲置淡出样式，避免临界窗口高度下显示／隐藏滚动条改变预览宽高并反复重排。

地图左栏预览按选择数量显示固定散叠样式：单张无背板，2 张一层，3–9 张两层，10 张及以上七层。所有背板与当前照片显示尺寸一致，围绕中心小幅旋转并向不同方向偏移，四周露出边角；当前照片保持完整、端正，右下角显示实际选中数量。各档预留相同空间，不推动下方布局；只复用当前照片缩略图，背板为简单图形，不增加照片解码，也不持续随机或播放动画。此效果仅用于地图左侧预览，不改变选择、定位或写入范围。

地图左栏按“照片与选择范围 → 当前定位 → 收藏地点 → 轨迹”排列，采用系统字体、细分隔线和原生展开控件。多选注明上方只预览当前照片，并汇总缺少定位、已有定位及读取失败数量；读取失败不计作缺少定位。GPS 基础信息已随导入读取，此汇总不等待完整 ExifTool 检查。当前照片的坐标详情按需展开，每项独立一行，可复制；定位草稿显示待写入数量。地图设置位于左栏标题右侧。

收藏默认显示前两项，可展开全部，保持已有顺序；名称只预览地点，“应用”才修改所选照片。只读项或保存中等禁用原因就近说明。无本次轨迹时收起内容，导入入口常驻；导入或加入新的历史轨迹后展开，切换照片不重置用户的展开选择。当前轨迹在前、历史在后；匹配说明明确使用全部带逐点时间的已导入轨迹及当前选择的照片。“补齐缺失定位”为主要动作，覆盖已有定位放入“更多匹配选项”；无法编辑的照片跳过，不加入定位修改。进度及错误保持可发现，常规隐私说明放入轨迹菜单。修改先暂存，可撤销，最后由共用“写入所有元数据”写入，不增加单独的定位保存入口。

高德搜索使用官方 JS API 的 AMap.PlaceSearch，输入后显示候选地点；选中候选只预览，点击“应用”才修改选中照片的位置，仍需手动保存。
收藏支持名称、备注、编辑和删除，保存为 WGS84，存放在应用私有 `Application Support/PhotoTrail/Favorites.json`，独立于公开代码。首次启动会复制旧 `GeoTagCN` 文件，原文件保留。点击收藏名称预览，点击“应用”设置选中照片的位置。
高德标记使用内嵌 SVG，不依赖默认图标的外部资源加载。应用菜单、主要窗口、设置及提示已加入简体中文。

单元测试方案设置 `PHOTOTRAIL_OFFLINE_TESTS=1`，不加载私人收藏、凭据或交互窗口。独立测试 bundle 标识避免打断日常应用；单元测试不等于真实界面或在线接口验收。

## 双页面界面

顶部“照片列表／地图定位”共用选择及未保存状态。照片列表负责整批筛选、批量操作和匹配结果复核；地图定位负责照片预览、地点搜索及纠偏。双击列表照片进入地图定位，返回时保留照片状态筛选、排序和选择。

列表显示保存状态、缩略图、文件名、时间、合并的定位列（上纬度、下经度）和上次轨迹匹配结果；绿色圈勾仅表示无未保存修改，缺少坐标也可以显示绿色。批量操作侧栏由工具条按钮展开或收起，面板宽 200 点，操作按钮统一填满可用宽度，采用相同控件底色和 1 点描边，图标固定 16 点宽、图文间距 7 点并左对齐；“撤销”固定在面板下方，其他操作独立滚动；写入统一使用窗口右上角的共用按钮。轨迹匹配设置按需展开，先预览再应用。上次匹配结果用于复核，不代表手动编辑后的当前定位；可筛选未成功的结果或清除记录。匹配结果保存在当前窗口会话中，重启后不恢复。

照片状态筛选使用紧凑菜单，避免常驻元数据分栏挤压按钮；各选项仍显示数量。常规照片状态与文件名筛选会移除不可见照片的选择。匹配结果筛选保留选择用于复核，工具条同时显示选择总数与当前可见选择数，批量操作仍作用于全部选择。

- 两个地图共用标准/卫星滑道、指南针及缩放/本机定位控件。搜索使用 regular 雾面玻璃，收起为 44 点圆形放大镜，展开为同高胶囊，遵循减少动态效果设置。入口距地图底边 52 点，避让比例尺；结果面板显示在搜索框上方，使用跟随应用亮暗外观的标准磨砂材质，避免 Liquid Glass 自动变亮。

- 选中照片停留 500 毫秒后，向当前地图服务查询省市区，仅用于显示。会话内按来源和坐标缓存；旧查询结果不能覆盖新选择，不写入照片。
- 本机定位错误区分权限和网络问题；无法确定位置时提示检查 Wi-Fi，并提供苹果官方说明入口，不把通用错误推断成已检测到 Wi-Fi 关闭。
- 列分隔拖动由本地事件处理器直接控制相邻两列，总宽度固定；其他表头操作沿用系统行为。

## 地图与表格实现

搜索控件在同一胶囊中切换材质：收起用 `Glass.clear`，展开输入时用 `Glass.regular`，保持 44 点高度及原来的动画和减少动态效果支持。结果列表使用 `regularMaterial` 标准磨砂，跟随应用亮暗外观以保证阅读。

高德地图画布通过 `.ignoresSafeArea(.container, edges: .top)` 延伸到浮动标题栏下，不再使用会复制边缘的 `backgroundExtensionEffect()`。`AMapWebView` 使用公开的 `obscuredContentInsets` 显式将网页遮挡边距归零（先赋不同值，避开 WebKit 的相等值短路），避免 WebKit 再为标题栏留出空白；搜索、图层切换和导航按钮仍由原有 SwiftUI 布局定位。

列宽拖动改为真实表头上的窄拖动区域，避免依赖全窗口鼠标监视器。移动分隔只调整左右两列；分隔获得焦点后可用方向键调节。测试覆盖表头命中、鼠标事件路径、相邻宽度总和、最小宽度和后续列保持不变。

### 左栏轨迹导入与转换缓存

源码开发版统一支持 GPX、KML、KMZ 导入，文件选择、拖放、目录导入、历史恢复及刷新共用同一读取入口；CSV 轨迹暂不支持。KML 读取 Placemark 内的 LineString、Track／gx:Track 和 MultiTrack／MultiGeometry 中的对应几何，每条线或子轨迹独立分段；逐点时间完整时复用原有保守匹配，没有逐点时间的路线仅供查看，匹配入口在没有带时间轨迹时禁用。整条路线的 TimeStamp 不扩展为逐点时间；空坐标形成断点，缺少时区、时间与坐标数量不一致、非法坐标或损坏 XML 拒绝导入。只将 absolute 高度作为海拔，相对地面高度不写入照片海拔。

KMZ 使用 macOS 自带 ZIP 读取工具读取包内 XML，不在磁盘解包；优先根目录 doc.kml，没有它时要求包内只有一个 KML。KML 与 KMZ 输入及展开的 XML 限制为 64 MiB，KML 最多 100 万个点。不读取网络链接、外部实体、图片、模型或其他附件。保留原文件身份及已有坐标缓存规则；照片生成与导出仍为 GPX。

界面范围仅为详情页左栏：照片预览、当前位置、收藏与轨迹统一纵向滚动，无切换页签。每个轨迹文件一行：眼睛图标仅控制地图显隐，不影响参与匹配的轨迹；点击名称选中并自动查看范围，省略号菜单与右键菜单提供刷新、缓存清理和移出本次操作。轮廓由本地 WGS84 坐标按比例绘制，保留断点；记录时间来自有效轨迹点时间戳，按本机时区显示，跨天包含日期，无时间明确标注。状态、进度、取消和重试均在对应行内，折叠时仍显示匹配进度和转换失败入口。

`GpxTrackLog.sourceURL` 绑定文件身份，重复导入替换同一条记录而不增加重复项。照片匹配仍使用原始 WGS84、时间与海拔，与显示勾选和高德缓存无关。从操作区移除不删除源文件、历史记录或转换缓存；菜单里的缓存清除仅清除转换结果。

`TrackLibrary` 在应用沙盒 `Application Support/PhotoTrail/Tracks/cache-v1.json` 原子保存版本化清单、只读安全书签、原始轨迹和高德 GCJ-02 结果；首次启动复制旧 `GeoTagCN` 缓存且不删除原件。目录 0700、文件 0600，不保存凭据。每个窗口首次只恢复历史记录，不自动加入本次操作区；读取一次缓存和可访问源文件，后续显隐使用内存。按坐标顺序和分段内容计算稳定 SHA-256 标识；源文件变化或无效结果不沿用旧缓存，损坏的缓存文件保留、不用空文件覆盖。原文件失联时保留缓存用于查看，但不恢复进照片时间匹配。历史恢复不触发高德转换；点击“加入”后才显示并参与本次操作。

轨迹卡片按标题、历史记录、本次轨迹、照片匹配操作排列。历史记录默认收起，展开显示轨迹轮廓、文件名、记录时间、缓存状态与“加入”按钮；已在操作区的记录不能重复加入。三个匹配按钮纵向等宽排列，保留补齐与覆盖的说明。导入后的结果弹窗取消，失败文件在卡片中提示，照片列表页提供查看入口。文件选择器保留。

新导入轨迹自动显示；使用高德时按本次列表顺序排队转换，一次只提交一个文件。等待、进度、取消和失败重试显示在对应行；失败或取消后继续下一条。苹果地图使用原始坐标无需转换，切换高德后自动排队处理可见且没有有效缓存的轨迹。历史轨迹加入时检查源文件；有效缓存直接复用，源轨迹变化才重新转换。原文件不可用时仅预览缓存，不加入照片时间匹配。

每条轨迹独立转换与显示，所有文件共用一个 JS 队列：每批最多 40 点，请求起始间隔至少 1.1 秒，QPS 限流最多延迟重试两次。单文件完整转换后保存并替换旧结果。刷新失败／取消保留旧轨迹，旧任务结果不能覆盖新请求。样式、选中范围及显隐不重新转换；重新加载地图直接重新绘制内存结果。错误提示只含固定文案和筛选后的服务错误码。


官方接口依据：[坐标转换及 40 点上限](https://lbs.amap.com/api/javascript-api-v2/guide/transform/convertfrom)、[Polyline](https://lbs.amap.com/api/javascript-api-v2/guide/amap-line/poly-line)。

地区查询实现：显式 completion + continuation 接收 WKWebView 异步返回值，避免 Void 重载丢失结果。

### 滚动条

照片列表、详情侧栏、照片条、批量操作、搜索结果、设置、首次引导和日志使用较细的 5 点圆角滑块。保留原生滚动、拖动和命中区域；滑块颜色随亮暗外观变化，增强对比度时提高可见性。停止滚动 3 秒后以 0.3 秒渐隐，重新滚动或鼠标进入滚动条区域时恢复；悬停及拖动期间不隐藏。启用减少动态效果时直接隐藏，不播放渐隐动画。应用内滚动条使用独立的隐藏计时，不修改 macOS 全局偏好。

## 元数据右栏读取与刷新

导入沿用基础元数据读取；列表出现后，每个窗口用单一后台队列补齐本地图片的 73 个可编辑白名单标签、兼容作者及所有可识别家族的展示读数（含 EXIF、IPTC、XMP、MakerNotes、ICC、Photoshop、容器与派生字段）。已有 XMP 同时读取原图的非 XMP 展示标签。同名标签采用 family-1 来源与 family-4 副本标识保留，不让 JSON 同名键覆盖；原始二进制内容仅显示引擎的摘要，不导出图片负载。选中图片的可编辑快照优先，其完整展示读数其次，其他等待任务排后；已开始的读取安全完成，不强杀进程。核心快照可先显示，只读目录未完成时标为“正在读取”，失败与未填写区分。缓存命中的选择立即呈现；未命中时有 100／150 毫秒短暂合并窗口，取消选择任务不会取消其他图片的后台预读。搜索附加字段复用已有完整读取。

窗口保留当前导入集合的读取缓存，移除图片时回收；按实际 URL、原图 URL、读取类型及两份文件版本核对，重复选择未变化的文件复用缓存。共享的跨视图缓存仍最多 64 份数据集。保存后及右栏 5 秒检查仍核对版本；手动重新读取清除相关 URL 的缓存，并重新入队。读取过程中来源改变则丢弃旧结果并重排，失败可通过重新读取重试。预览和保存继续独立检查冻结目标与磁盘版本，缓存不会绕过这些检查。缓存只在会话中保留，重开窗口重新读取。

工作区进度显示已读取、总数及失败数，进度条按可编辑字段和完整字段两阶段累计，避免第一阶段完成前照片计数停在零。一次排队至少 100 张未完成读取的本地照片时，照片工作区显示元数据准备页，暂不构建列表和检查器；读取结束后自动恢复。准备页提供两阶段计数和失败数，可切换到其他应用；“暂停读取”返回工作区浏览已缓存的数据，顶部“继续读取”恢复排队任务，已开始的有限批次安全完成。每个窗口默认最多同时执行四个读取任务，按可用核心数留出两核，低核心设备降低到至少一个任务，复用现有 ExifTool 有限批处理、字段格式和文件版本校验。小批量读取仍可边读边浏览；读取进度独立刷新。

导入入口（导入照片、拖入、Finder 打开及轨迹导入）共享覆盖应用工作区的进度页，分为扫描、基础信息导入和轨迹读取；大批量照片接着进入元数据准备页。目录枚举在后台执行，继续保留安全作用域访问、过滤、去重及重复文件提示。导入过程中暂不接受编辑、保存或移除照片，系统其他应用仍可正常使用。已处理数量按当前阶段的文件／请求数量显示，失败的读取也计入处理数量，不伪造成功。

基础导入和元数据准备页只显示“全部导入预计剩余约…秒”，不分别显示两个步骤的剩余时间。基础导入尚未结束时，将其剩余耗时与同窗口已采样的元数据每张耗时相加；元数据读取阶段合计全部尚未完成的可编辑字段和完整字段读取。后续步骤没有可靠样本或仍有未知耗时的待导入轨迹时，显示“正在估算全部导入剩余时间…”，不以已知阶段代替总时间。速度样本只在当前窗口内复用，不持久化，实际速度变化时估算会调整。本批次导入照片超过 300 张时，两步准备页均提示照片较多、处理需要一些时间；批量照片导入共用连续的居中等待布局，基础信息阶段标为“第 1 / 2 步：导入文件”，元数据阶段标为“第 2 / 2 步：准备元数据”，分别提供已处理数量。目录扫描总数尚未知，不显示百分比；仅轨迹或小批量照片导入不承诺额外准备步骤。返回工作区后的后台读取也合计剩余元数据工作，不显示单独阶段时间。进度计数独立观察，基础导入通知间隔约 150 毫秒，避免计数刷新重建整个工作区。

列表“原标签”旁显示等待、读取或失败状态，尚未完成不显示虚构的零。“原标签”统计已读取的原始元数据标签（含厂商私有、色彩及容器信息），排除 File／System 文件属性、Composite 派生字段及 ExifTool 引擎信息；命名空间／IFD 与同源副本分开，关键词数组计一个标签。它表示信息量，不是完整率。计数反映最近的磁盘快照，保存后重读更新；“已编辑”为当前尚未保存的字段数，包含新元数据草稿与旧日期／地图定位草稿。Photos 图库项目不参加本地文件完整预读计数。

## 文件重命名（源码开发版）

第三个标签页使用三页共享的本地照片集合；右侧“导入照片”复用统一导入与去重，单独文件集合不再存在。照片图库项目和无本地路径的照片不能直接改名，目录与符号链接本身不参与。元数据草稿必须先保存或放弃，写入期间不能执行改名。导入照片后通过原生目录选择器授权所在目录，用于扫描配对、检查重名和安全改名；已由照片导入授予的目录权限会复用，未授权时不扫描目录并阻止执行。只处理预览中的文件，不递归遍历。规则可启停、排序、复制，提供文字、字符、大小写、兼容名称、日期、数字／罗马数字／字母序列、音乐／照片标签、尺寸、父目录／路径、文件列表及正则表达式等 97 个动作入口；另有分段筛选和高级设置。动作入口不代表全部第三方参数已完全复刻。

重命名前若存在任意照片的元数据或定位草稿，会询问是否先保存两个页面的全部修改；也可取消并继续编辑。保存仍走原有摘要偏好、备份、版本检查与回读流程，完成后刷新改名预览，不自动执行改名。保存失败、取消或部分成功时保留剩余草稿，重命名执行层仍禁止改名。保存成功后用户核对新预览，再确认执行。

重命名页进入后开始生成预览，读取照片信息、扫描已授权目录的关联文件、计算规则和冲突；加载期间显示居中的半透明浮窗，读取阶段显示数量进度与基于近期速度的当前阶段时间估算；扫描总数未知或最终规则计算期间显示不定进度条，不虚构完成时间，保留修改规则和切页能力。切页后已启动任务继续完成，返回页面时重新核对并复用有效缓存；不在其他页面提前生成重命名预览。预览保存文件信息、标签和规则中间名称，不载入全部原图或计算执行用的内容哈希。

重命名每次启动默认处理全部导入照片，手动改为选中照片后，同一会话切页保留范围，不因选择变空而扩大范围。照片选择在三页同步；高亮预览行不改变“全部／选中”的操作范围。关联文件列入完整预览；表格整行右键可从共享列表移除照片，先确认、可撤销且不删除磁盘文件。当前预设显示于左栏顶部的渐变圆角卡片，浅色模式采用蓝紫柔光、暗色模式采用深色靛蓝，两种主题共用布局；常用与个人方案在“切换与管理…”浮窗统一管理；启动恢复最后一次使用的方案，未保存规则不自动覆盖命名预设。预览表始终显示预览、原文件名、步骤结果、新文件名、状态五列。状态列固定 120 点并保持最右侧；未选择操作时中间列提示“选择操作以查看”，选择后标题改为“第 N 条执行后”并显示对应中间结果。三个名称列允许调宽，列宽在切页及重启后保留；窗口宽度改变时适配可见区域，保持状态列可见。操作仅单项高亮，点击另一操作或取消选择时，原操作的输入框退出编辑焦点；标签模板等多行输入框跟随浅色／暗色主题。选择或取消选择操作不新增或移除列。不再有列表下方逐步明细。

名称可针对主体、完整名称、带点或不带点的扩展名处理；字符位置从零计，按 Unicode 字形簇计数。拍摄时间按可编辑来源优先级读取，存在偏移才换算时区，未记录时区保留墙上时间；可设置夜间归入前一日期。缺少日期／模板字段默认整组保持原名。数字序列提供手动值与十个持续计数器，预览不消耗计数，全部执行成功后才推进；执行前核对计数是否变化。后续规则因缺字段跳过某一组时可能留下编号空隙，下一批从已分配的最高序位之后继续，不复用后面已分配的编号；每目录编号按本批最高序位推进。同一持续计数器不能在一个方案中重复使用。

“重命名设置…”打开独立设置弹窗，集中管理“照片及关联文件一起改名”、照片文件扩展名／附属文件扩展名、排序、文件名冲突及拍摄时间来源优先级；修改即时刷新预览，关闭弹窗不执行改名。“照片及关联文件一起改名”默认开启，扫描同目录同主体的照片及旁车，全部列入预览；主文件产生主体，其他成员保留各自扩展名，最终冲突后缀整组一致。照片文件扩展名从左到右决定主文件优先级，以该组实际存在的首个格式计算新名称，其他成员跟随；附属文件扩展名只决定参与格式，顺序不影响优先级。可关闭配对；已加载 XMP 来源的照片必须保持照片与旁车实际配对，否则阻止执行。冲突可阻止执行或添加数字／字母后缀；后缀预设支持无分隔符、下划线、连字符和括号，数字支持 2／3／4／5 位最小宽度（01／001／0001／00001），溢出位数不截断，关联组共享后缀。旧预设保持数字 _001、字母 A 的原有默认格式。不覆盖已有文件。执行前重新检查源身份，暂存全部变化源后再提交目标，支持交换及循环改名，并回读 SHA-256 确认内容。文件操作采用不覆盖的原生改名接口，不能保证断电时跨多个文件的事务原子性。

执行重命名时用全局居中进度遮盖工作区，阻止切换页面和编辑，显示检查、准备修改、改名与结果核对的当前阶段数量及累计进度；数量包含关联文件，不以照片条目数代替文件数。中央保留“停止并恢复”；停止后按钮禁用，恢复期间继续显示进度，完成或报告需人工恢复后才解除遮盖。每个 1 MiB 校验读取块及时释放临时对象并检查停止请求，同目录访问书签在本次执行中复用。原文件内容核对、冲突保护和恢复日志仍保留。

成功后保持照片 ID、选择与配对关系，更新名称、元数据来源和撤销基线，清空旧路径编辑撤销记录及读取缓存，后续保存使用新路径。执行记录持久保存原名、目标、暂存位置、身份、内容哈希与可获取的安全作用域书签，可在“执行记录与恢复”恢复原名；文件内容后来被编辑或原名被占用时拒绝恢复。中断时先尝试恢复，失败保留记录；当前窗口涉及未恢复文件的照片禁止继续元数据写入。恢复失败或外部移动后应核对实际路径，不自动猜测。

预设为 PhotoTrail 自有版本 1 JSON，可保存、导入、导出；不支持直接导入第三方程序的预设、Droplet 或 Finder 扩展。模板使用 `<标签>`，提供候选与已读实际标签；候选存在不代表当前格式能提供读数。模板可能包含文件名非法字符，须核对状态。正则替换支持捕获组和 `\U/\L/\u/\l/\E` 大小写转换，重排可选择整段匹配。仅提供一个任务级排序键。兼容名称动作未经 Mac OS 9、DOS 或外部 NTFS 卷验收。

## 设备目录与加载优化（源码开发版）

启动只在后台恢复历史轨迹缓存，不重新解析全部原始轨迹；历史不会自动进入本次操作区或照片匹配。加入历史轨迹和刷新时在后台解析原文件，保留书签权限、源变化及转换有效性检查；读取期间禁止重复请求，移除或新导入产生的较新状态不被迟到结果覆盖。缓存恢复完成前暂缓写回，并优先保留本次已导入的数据；损坏缓存仍保留原文件。重命名执行历史仅在打开“执行记录与恢复”时后台读取。KML 解析与表格列宽辅助查找避免重复数组复制和重复遍历。

EXIF 的 IFD0:Make／Model、XMP 的 tiff:Make／Model 编辑器提供品牌、机型搜索与已核实值选择，仍保留自定义文本。选择只填当前字段，不连带改写其他来源或厂商私有信息；统一值、预览、草稿、备份、保存和回读仍走原路径。当前范围、证据和未覆盖情形见[设备目录](DEVICE_CATALOG.md)。

元数据面板每轮构建复用一次所选照片的合并值和编辑资格，搜索无须读取值时跳过值投影；完整多选汇总仍等待该批数据齐全。快速切换照片时，取消的预览任务不更新画面，缓存按原始照片 ID 回填，已移除照片的结果被忽略。导入后后台预读、选中插队、缩略图按需加载、地图可见范围限量与重命名预览防抖继续保留。


## 元数据编辑器与右栏（源码开发版）

单字段与批量编辑窗口采用 880 × 660 的 4:3 布局，左侧编辑、右侧当前内容／逐照片修改预览、底部固定操作。73 个白名单字段分别使用单行文本、多行描述、作者／列表、日期与六项偏移、数值／分数、枚举、闪光状态、品牌／型号控件。数值显示单位与范围，IPTC 显示字节限制，国家代码显示三字母说明。枚举保留已有未知值的显示；闪光灯提供常用状态，也允许原始代码。时间文本保留秒、亚秒和偏移，日期控件继续复用原有精度与时区路径。

设备选择不再使用独立的名称切换开关：在型号菜单中直接点击商品名或元数据型号；同一行对应同一设备，相同值合并显示。仅有官方商品名证据的选项标为“仅商品名”，不提供未核实的元数据值，也不作为制造商候选。最终输入框始终可手动修改；选择品牌时，制造商编辑器填入该品牌已核实的 Make，型号编辑器只改变筛选范围。

右栏按字段名、值、技术标签分层；右侧箭头提供编辑入口，待保存与只读均有文字和图标，顶部给出“选择字段 → 编辑并预览 → 保存照片”的顺序。单击选择、⌘ / Shift 多选、双击编辑、搜索筛选和右键批量操作继续使用原生列表与既有路径。只读字段不因界面重设计获得写入权限。加入待保存不会立即改写文件，保存、备份、版本检查和回读保持原有边界。

字段提供“常用字段／完整字段”切换，并记住选择。两者共用原生分组字段行与同一编辑窗口，仅字段范围不同。常用视图覆盖设备、主要时间、作者、版权、标题、说明和关键词，保留空字段、原有来源与权限，不合并同名标签写入。搜索包含全部已读字段；取消隐藏字段、仅有值、仅待保存及显示全部附加字段等显示设置。日期名称标明 EXIF、IPTC、XMP 或文件系统来源。

### 元数据字段紧凑列表

字段行采用左侧名称与精确来源、右侧数值的布局；名称和普通数值为 13 点，来源为 10 点；日期时间字段统一分两行，上行年月日时分秒为 15 点，下行时区与亚秒为 11 点灰字（仅日期／仅时间沿用同样层次），名称列在 140–240 点间适应右栏宽度，行内容至少 40 点高，上下间距为 6 点，以清晰分隔线区分条目。数值最多显示两行，悬停可读完整值，原有复制与编辑入口保留；待保存用橙点，不能编辑时显示锁图标。单击选择、⌘／Shift 多选、双击编辑及批量操作不变。常用字段与完整字段均单击选择、双击或点击铅笔打开既有编辑器；不再使用独立快速表单。批量复制日期默认以 EXIF 拍摄时间为来源，每张照片使用自身的来源值，缺失时跳过。

新增可编辑字段包括文件创建／修改时间、IPTC DateCreated／TimeCreated、EXIF Orientation／XResolution／YResolution／ResolutionUnit、XMP 镜头序列号、评分和标签。IPTC 日期和时间可分别输入，也可从完整拍摄时间复制并提取对应部分；IPTC TimeCreated 要求显式时区，来源没有时区时提示输入错误，不让引擎默默补成 UTC。文件时间沿用 JPEG 原图编辑、备份、草稿、文件版本检查及保存流程；先保存元数据，再由系统设置实际文件属性并回读，不依赖外部 SetFile 命令。支持亚秒及显式时区，未记录时区按本机时区解释；文件时间不能清除。已有 XMP 来源的文件系统属性尚未接入编辑，避免把旁车时间误当原图时间。方向只修改方向标签，不旋转像素；分辨率只修改打印分辨率，不改实际图像尺寸。像素尺寸、容器结构、派生值及未验证的厂商标签保持只读；GPS 使用地图定位流程，Finder 标签使用已有照片标签操作。

## 批量处理与浏览性能（0.5.2）

本地照片与 XMP 的日期／定位保存分别使用最多 32 个文件任务；图片导入最多 8 个任务，轨迹解析保留原上限。JPG／TIF 扩展名复用已有 JPEG／TIFF 类型资格，不再为别名额外启动格式检测进程。保存任务先补入下一文件，再按最多 32 条或约 150 毫秒合并结果到主线程；成功文件更新保存基线，失败文件保留草稿，进度计数仍按实际文件数。备份、XMP 来源切换和 Finder 标签失败语义不变。每个任务结束后回收它创建的沙箱目录。保存的文件处理、备份和写入阶段提供系统 signpost，总结日志记录文件数、失败数和总耗时，不在新增性能日志中记录路径或坐标。

保存期间暂停尚未开始的元数据预读，已开始的读取安全完成；结束后按文件版本检查缓存并继续读取。元数据读取状态按照片行更新，整体读取进度使用增量计数；本地原图的兼容作者字段复用已经读取的精确来源，XMP 对应原图仍单独读取。常规文件版本轮询在后台执行，保存期间暂停。

元数据列表缩略图按屏幕倍率使用最长边约 80 点对应的像素规格；定位页底部照片条根据实际显示宽度及屏幕倍率，在 160／256／384／512／768／1024 像素档位中选择足够的规格。左上角大预览保留最长边 1024 像素，并使用独立缓存，不再回填全局照片状态或供小图绕过尺寸规格。本地图片解码最多并发 2 项，当前照片大预览优先于等待中的普通缩略图；已经开始的解码安全完成。照片图库传输继续按原规格读取与估算缓存。同一照片、路径、尺寸和倍率的并发请求复用一个加载任务；离屏消费者取消后，仍有消费者的请求继续，无消费者的等待解码取消。小图与大预览各自最多缓存 384 项，分别使用 64 MiB 的估算解码内存预算；实际内存还包括画面持有的图像和正在解码的图像。照片定位保存不无条件清空缩略图缓存。缩略图与元数据读取缓存均只在当前运行中保留，退出后重新准备；更新沿用正式版的沙盒标识、设置及持久化轨迹缓存。

照片选择、读取进度及焦点变化复用列表的筛选、计数、元数据面板的所选照片快照和照片条排序结果；照片数据、筛选、搜索、排序或相机时区变化时更新相关结果，日期解析按照片时间和时区复用。数据变化使用独立标记，撤销、重做及撤销后继续编辑均会刷新缓存；配对、待保存筛选及排序规则不变。地图显示全部照片时，选择变化更新高亮及边缘指示，不重建整批照片几何与分组；只显示所选照片时仍随选择更新。照片条右键菜单在打开时构建，避免滚动布局逐项遍历全库或读取剪贴板。列宽及滚动条辅助控件复用已找到的原生对象，滚动容器被替换时重新查找。

ExifTool 并发调用在约 5 毫秒窗口内合并为最多 4 条独立命令，每个命令保留自己的输出与退出状态；由专用原生线程调度，最多同时运行 8 个短期进程；按可用核心数留出 2 核，低核心机器至少允许 1 个进程，批次结束后退出；调度不依赖正在等待结果的 Swift 协作线程；日期／定位写入使用异步结果通知，不阻塞 Swift 协作线程等待进程。改变进程配置或命令边界的调用保留原单次执行方式。多命令批次异常时不自动重放写入；已有元数据编辑回读与未知结果处理不变。旧日期／定位保存仍依据写入命令结果判定，不声称新增逐字段回读。
